# מדריך הפעלה ופרסום

## א. הפעלה מקומית (ללא חשבון, ללא עלות)

דרישות: Node.js 22 ומעלה.

```bash
npm install
npm test            # בדיקות אוטומטיות
npm run dev         # שרת פיתוח, בכתובת http://localhost:5173
```

- **ללא הגדרות:** האתר עולה במצב "ללא שירות נתונים": כל 114 רשומות המיפוי בקריאה בלבד, חיפוש, כרטיסי נושא ובדיקת התאמה מקומית. כניסה ושמירה אינן זמינות, ונאמר זאת במפורש.
- **מצב הדגמה:** פתחו `http://localhost:5173/?demo=1`. נתונים מלאכותיים בדפדפן בלבד, עם חשבונות מלאכותיים (מורה, רכז, מנהל) ומעבר ביניהם. לא נשלח דבר לשום מקום. "איפוס נתוני הדגמה" מנקה.

## ב. חיבור לשירות אמיתי (Firebase, ללא תשלום)

1. ב־[Firebase console](https://console.firebase.google.com) צרו פרויקט. **אל תשדרגו ל-Blaze ואל תזינו אמצעי תשלום.**
2. Build > Authentication > Sign-in method: הפעילו **Email/Password**. תחת Settings > Authorized domains הוסיפו את הדומיין שבו האתר יפורסם.
3. Build > Firestore Database: צרו מסד (מצב production, אזור אירופה, למשל `eur3`).
4. Project settings > Your apps: הוסיפו Web app, והעתיקו את ההגדרות לקובץ `.env.local` (תבנית ב-`.env.example`). אלה מזהי לקוח ציבוריים ולא סודות.
5. פרסום הכללים:
   ```bash
   npx firebase login
   npx firebase deploy --only firestore:rules,firestore:indexes --project <PROJECT_ID>
   ```
6. הרשמו באתר עם הכתובת שלכם ואמתו אותה במייל.
7. הגדרת **מנהל ראשון** (חד־פעמי), באחת משתי דרכים:
   - **בקונסולה:** Firestore > צרו אוסף `roles` > מסמך עם מזהה = ה־UID שלכם (מוצג ב־Authentication > Users) ושדות `role` = `admin`, `grantedBy` = `manual`, `grantedAt` = מספר כלשהו.
   - **בסקריפט:** הורידו מפתח שירות (Project settings > Service accounts), שמרו אותו **מחוץ לפרויקט**, והריצו:
     ```bash
     export FIREBASE_PROJECT_ID=<PROJECT_ID>
     export GOOGLE_APPLICATION_CREDENTIALS=/path/to/key.json
     node scripts/bootstrap-admin.mjs --email you@example.com
     ```
8. היכנסו לאתר > ניהול > "מחלות וכללים" > **ייבוא מיפוי המקורות** > תצוגה מקדימה > אישור. זה מייבא את 114 הרשומות ומפרסם את הקטלוג.
9. הגדרות: כתובת האחראי, קישור הטופס, יעד טיפול, ומוסדות (ייבוא CSV).
10. מנהלים נוספים: הם נרשמים ומאמתים כתובת, ואז מנהל קיים ממנה אותם מ"משתמשים והרשאות".

## ג. בנייה ופרסום (רק לאחר אישור בעל המוצר)

```bash
npm run build       # יוצר את התיקייה dist
```

האתר סטטי ומשתמש בניתוב `#`, ולכן רענון קישור ישיר עובד בכל אירוח:
- **Firebase Hosting (חינם):** `npx firebase deploy --only hosting --project <PROJECT_ID>`.
- **GitHub Pages:** הפעילו Pages מ-GitHub Actions ואז הריצו ידנית את `deploy-pages.yml`. הגדירו ב-Settings > Variables את `VITE_FIREBASE_*`.

**אין לפרסם לפני אישור.** הקבצים והזרימות מוכנים ואינם מופעלים.

## ד. גיבוי ושחזור

- **ידני מהאתר:** ניהול > "גיבוי, דוא״ל והיסטוריה" > הורדת גיבוי (תוכן בלבד). שחזור מאותו מסך.
- **אוטומטי שבועי (מוכן, לא מופעל):** מאגר GitHub **פרטי**; הוסיפו סוד `FIREBASE_SERVICE_ACCOUNT_JSON` ומשתנים `FIREBASE_PROJECT_ID` ו-`ENABLE_BACKUP=true`. הקובץ נשמר כ-artifact ל-90 יום.
- **שחזור משורת הפקודה:** `node scripts/restore.mjs backups/<קובץ>.json`. הסקריפט מפעיל מחדש מחיקות מחזור לפי יומן המחיקות, כך שתלמידים ממחזור שנסגר אינם חוזרים.
- **בדיקת שחזור:** נבדק בבדיקות אוטומטיות על נתוני ניסוי (`tests/api.test.ts`). לא נבדק על Firebase אמיתי. מומלץ לבצע פעם אחת בפרויקט ניסוי לפני העלאת נתוני אמת.

## ה. דוא"ל

- **אימות כתובת ואיפוס סיסמה:** Firebase שולח אוטומטית (מכסות ב-`ARCHITECTURE.md`).
- **התראות מנהל ותשובות למורים:** נשמרות בתור. לשליחה אמיתית: הגדירו ספק SMTP (למשל חשבון דוא"ל ייעודי), והוסיפו ל-GitHub את הסודות `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM` ואת המשתנה `ENABLE_OUTBOX=true`. עד אז ההתראות באתר פועלות, והתור מציג "טרם נשלחה".

## ו. סיום מחזור (פעם בשנה)

ניהול > מחזורים: ודאו שהמורים דיווחו מה בוצע והרכזים תיקנו; הקלידו את מזהה השנה לאישור; "סגירת המחזור". הפעולה מוחקת שמות וכינויי תלמידים, מעדכנת היסטוריה לא מזהה, ורושמת יומן מחיקות.

## ז. בדיקת כללי ההרשאות (לפני פרסום)

דורשת Java (גרסה 11 ומעלה):
```bash
npm run test:rules
```
